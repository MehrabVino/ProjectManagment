# Learning Paths

Each path uses the same progression. The implementation language and tools may change; the engineering decisions do not.

| Stage | Outcome |
| --- | --- |
| 01 - Foundation | Clear naming, small functions, Git workflow, project decisions |
| 02 - Boundaries | Modules, dependency direction, contracts, error handling |
| 03 - Quality | Unit, integration, and end-to-end test strategy |
| 04 - Patterns | Introduce patterns only for an identified pressure point |
| 05 - Delivery | Configuration, reproducible builds, CI, releases |
| 06 - Operations | Logging, metrics, tracing, recovery, performance |

Choose one specialization after Stage 02:

- [Software products](software.md)
- [AI products](ai.md)
- [Game products](game.md)
